# AI Job Resilience — 4-Week Study Plan

> **Goal:** Build enough AI fluency in 30 days to be job-resilient, credibly technical, and strategically positioned — leveraging your existing cloud, project management, and GenAI implementation background.
>
> **Daily commitment:** ~90 minutes/day. Split across morning + lunch or after work.
>
> **Three pillars running in parallel:**
> - Pillar 1 — Understand AI (how it works, what it can't do, where it's going)
> - Pillar 2 — Build with AI (prompting, APIs, agents, real tools)
> - Pillar 3 — Lead AI work (strategy, governance, ROI, team enablement)

---

## Week 1 — AI Foundations
**Theme:** Build the mental model. Understand what AI is doing under the hood so you never sound lost in technical conversations.

---

### Monday — How LLMs work

| Time | Task | Notes |
|------|------|-------|
| 30 min | Watch: 3Blue1Brown "But what is a neural network?" + Andrej Karpathy's intro to LLMs | YouTube — both free. Don't skim. This is the mental model everything else builds on. |
| 45 min | Read: Anthropic's prompt engineering overview (docs.anthropic.com) | Focus on system prompts, user/assistant turns, and what "temperature" actually does. |
| 20 min | Reflection: write 5 bullet points — "how an LLM generates a token" | Rubber-duck it. If you can't explain token prediction simply, rewatch 5 min of the Karpathy video. |

**Resources:**
- [3Blue1Brown neural nets](https://www.youtube.com/watch?v=aircAruvnKk)
- [Karpathy LLM intro](https://www.youtube.com/watch?v=zjkBMFhNj_g)
- [Anthropic prompt engineering docs](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

---

### Tuesday — Prompt engineering

| Time | Task | Notes |
|------|------|-------|
| 30 min | Read: all of Anthropic's prompt engineering guide — system prompts, chain-of-thought, XML tags | Directly applicable to your GenAI PIC role — you'll use this immediately. |
| 45 min | Practice: open Claude.ai, build 5 prompts for real work scenarios | Try: status report drafting, risk log summarisation, meeting notes → action items. Save the best ones. |
| 20 min | Learn: what hallucination is, why it happens, how to reduce it | Search "Claude hallucination reduction prompting" — relevant to your CDP responsibilities. |

**Resources:**
- [Anthropic prompt engineering guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

| Time | Task | Notes |

| 30 min | Watch: "RAG explained in 5 minutes" (search YouTube) | RAG = Retrieval Augmented Generation. This is how enterprise AI avoids hallucinating on internal docs. |
| 25 min | Apply: sketch how RAG could work for HDB project documentation | What docs exist? What questions would stakeholders ask? Draw the flow on paper or Miro. |

**Resources:**

| Time | Task | Notes |

| 30 min | Build: a prompt template library — 5 templates for recurring work tasks | Suggested: status report → narrative, meeting notes → RAID log, requirements → user stories, email → exec summary, doc review → risk flags. |
| 15 min | Reflect: what do you still feel fuzzy on from this week? | Write 3 questions you'd struggle to answer confidently. These become your Week 2 starting points. |

## Week 2 — Build and Integrate
**Theme:** Get your hands dirty. Ship something using the Anthropic API — a real working tool, not a tutorial clone. Your React/TypeScript background from your side projects gives you a head start here.

---

### Monday — API basics and environment setup

| Time | Task | Notes |
|------|------|-------|
| 30 min | Read: Anthropic API docs — messages endpoint, model params, system prompts via API | Understand the difference between the playground and a real API call. |
| 40 min | Set up: get your API key, run your first `curl` call, then replicate in Node.js | Use your existing WSL Ubuntu environment. One successful API call is today's win. |
| 20 min | Experiment: try changing `temperature`, `max_tokens`, `system` — observe what changes | Keep a notes doc: what does each param actually do to output quality? |

**Resources:**
- [Anthropic API docs](https://docs.anthropic.com/en/api/getting-started)
- [Messages API reference](https://docs.anthropic.com/en/api/messages)

---

### Tuesday — Tool use and structured output

| Time | Task | Notes |
|------|------|-------|
| 30 min | Read: Anthropic tool use docs — how function/tool calling works | This is how AI connects to real systems. Critical for building anything agentic. |
| 45 min | Build: a small Node.js script that calls Claude and returns structured JSON | Try: "given this meeting transcript, return JSON with: summary, decisions[], action_items[], risks[]". |
| 20 min | Study: prompt patterns for reliable JSON output — XML tags, explicit schema instructions | The goal is deterministic structured output, not prose. This is the foundation of every AI pipeline. |

**Resources:**
- [Anthropic tool use docs](https://docs.anthropic.com/en/docs/build-with-claude/tool-use)
- [Structured output patterns](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

---

### Wednesday — RAG in practice

| Time | Task | Notes |
|------|------|-------|
| 30 min | Read: how embeddings + vector search work in practice — pgvector or Pinecone | Build on Thursday's conceptual understanding. Now see how it's actually implemented. |
| 45 min | Tutorial: follow a RAG quickstart using LangChain or LlamaIndex | Pick one. The goal is to see the full pipeline: ingest → chunk → embed → store → retrieve → generate. |
| 20 min | Apply: what would a RAG system over HDB project docs look like? Write the spec | What's the data source? What queries would it serve? What's the risk if it halluccinates? |

**Resources:**
- [LangChain RAG quickstart](https://python.langchain.com/docs/tutorials/rag/)
- [Pinecone quickstart](https://docs.pinecone.io/guides/getting-started/quickstart)
- [pgvector (Postgres)](https://github.com/pgvector/pgvector)

---

### Thursday — Agents and MCP

| Time | Task | Notes |
|------|------|-------|
| 25 min | Read: what is an AI agent? Agentic loops, tool chaining, when agents make sense | Key distinction: a single LLM call vs a loop where the model decides its next action. |
| 25 min | Read: Model Context Protocol (MCP) — what it is, why it matters for enterprise AI | MCP is how AI tools connect to data sources and systems. Relevant to your GenAI PIC work. |
| 40 min | Explore: Claude Code or a simple agentic script — a task that requires 2+ tool calls | Try: "search for X, summarise findings, write a recommendation" as a multi-step agent. |

**Resources:**
- [Model Context Protocol](https://modelcontextprotocol.io)
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code)
- [Anthropic agents overview](https://docs.anthropic.com/en/docs/build-with-claude/agents)

---

### Friday — Build your portfolio project (start)

| Time | Task | Notes |
|------|------|-------|
| 20 min | Decide: what are you building for your portfolio project? | Suggested: AI-powered project status report generator, or a RAG Q&A over your team's documentation. Pick what's most relevant to your work. |
| 60 min | Start: scaffold the project, wire up the API, get a basic end-to-end working | Don't polish. Get the happy path working: input → Claude API → output. |
| 10 min | README: write the first draft — what it does, why it exists, how to run it | A project without a README doesn't exist to recruiters or clients. |

---

### Saturday — Polish and test

| Time | Task | Notes |
|------|------|-------|
| 60 min | Continue: add error handling, improve prompts, test edge cases on your project | What breaks it? What makes the output worse? Fix the two biggest issues. |
| 30 min | Read: AI safety basics — alignment, jailbreaks, prompt injection | As a GenAI PIC you'll be asked about this. Understand the threat model at a conceptual level. |
| 20 min | Share: push project to GitHub, even if rough | A public repo with commits is evidence. Perfect is the enemy of visible. |

---

### Sunday — Rest or review

| Time | Task | Notes |
|------|------|-------|
| 20 min | AI news digest: The Batch or Willison's blog | Stay current. Note one thing that surprised you. |
| 15 min | Preview Week 3: skim an AI governance framework (EU AI Act summary, or Anthropic's responsible AI page) | Week 3 is strategy-heavy. Get a feel for the terrain. |

## Week 3 — AI Strategy and Governance
**Theme:** This is your edge over pure engineers. Learn to think about AI at the org level — risk, ROI, change management, responsible AI. Your CDP, BCP, and governance background maps directly here.

---

### Monday — AI risk and responsible AI

| Time | Task | Notes |
|------|------|-------|
| 30 min | Read: Anthropic's model card and responsible scaling policy | You're recommending AI to clients. You need to know the failure modes and safeguards. |
| 30 min | Read: EU AI Act — what it means for enterprise AI deployments (find a plain-English summary) | Clients in regulated industries (like HDB / government) will ask about this. Know the basics. |
| 30 min | Draft: a one-page AI risk register template | Columns: risk, likelihood, impact, mitigation, owner. Map it to your existing RAID log format. |

**Resources:**
- [Anthropic responsible scaling policy](https://www.anthropic.com/responsible-scaling-policy)

---

### Tuesday — AI governance frameworks

| Time | Task | Notes |
|------|------|-------|
| 30 min | Read: NIST AI Risk Management Framework (AI RMF) — executive summary only | The standard enterprise clients and auditors will reference. Know the four functions: Govern, Map, Measure, Manage. |
| 40 min | Build: an AI governance checklist for a new AI implementation at a client | Draw from your CDP experience. Include: data handling, model selection, human oversight, audit trail, rollback plan. |
| 20 min | Apply: map your HDB GenAI Implementation PIC responsibilities against the NIST RMF | Where do your current responsibilities sit? What gaps exist? |

**Resources:**
- [NIST AI RMF](https://www.nist.gov/system/files/documents/2023/01/26/AI%20RMF%201.0.pdf)

## Week 4 — Specialize and Position
**Theme:** Pick the lane where your cloud + AI + PM background creates a defensible position. Then make it visible. By end of this week you should have a portfolio, a clear positioning statement, and something public to point to.

---

### Monday — Pick your niche

| Time | Task | Notes |
|------|------|-------|
| 30 min | Research: three possible niches — read 5 job descriptions for each | Option A: GenAI Implementation Lead (consulting). Option B: AI Product Manager. Option C: Cloud AI Architect. |
| 30 min | Decide: which niche fits best given your background, interests, and market demand | Don't overthink it. You can adjust. Pick the one where you'd be most credible in 6 months. |
| 30 min | Map: what does "job-resilient in AI" look like for your chosen niche in 12 months? | Skills needed, projects to have done, titles to target, companies to watch. |

---

### Tuesday — Polish your portfolio project

| Time | Task | Notes |
|------|------|-------|
| 60 min | Polish: take your Week 2 project and make it presentable | Better README, cleaner code structure, working demo, screenshots or a short screen recording. |
| 20 min | Write: a case study paragraph — "what I built, why, what I learned, what I'd do differently" | This is your interview answer and your LinkedIn post. One tight paragraph beats a long essay. |
| 15 min | Deploy or share: Vercel, GitHub Pages, or even just a public GitHub link | Something with a URL you can paste into a message. |

---

### Wednesday — Build in public

| Time | Task | Notes |
|------|------|-------|
| 30 min | Write: LinkedIn post 1 — "one thing I learned about AI this month that surprised me" | Personal, specific, honest. No fluff. Tag it to your actual work context where relevant. |
| 30 min | Write: LinkedIn post 2 — "what AI is actually good at in enterprise project delivery" | Draw from your HDB/Nimbus experience. Specific > generic. |
| 30 min | Optional: write a short internal Accenture thought leadership piece on GenAI lessons learned | Even 400 words shared internally builds your reputation as the "AI person" on the team. |

---

### Thursday — Interview and conversation prep

| Time | Task | Notes |
|------|------|-------|
| 30 min | Prepare: answers to the 5 most common AI role interview questions | "How have you implemented AI?", "What's your approach to AI governance?", "Walk me through a prompt you've engineered", "How do you measure AI ROI?", "What are the limits of LLMs?" |
| 30 min | Prepare: your "AI positioning statement" — a 60-second answer to "tell me about your AI experience" | Tie together: your GenAI PIC role, the tools you've built, your governance work, and your niche. |
| 30 min | Practice: say it out loud, record yourself, adjust | Most people skip this. Don't. The first time you say it out loud in an interview shouldn't be the first time. |

---

### Friday — Final portfolio review (output day)

| Time | Task | Notes |
|------|------|-------|
| 45 min | Review: go through all four weeks' deliverables — what exists, what's missing, what's rough | Triage: what can you finish today? What do you carry forward? |
| 30 min | Finalise: your LinkedIn profile — headline, about section, experience bullets | Your headline should now say something like "Cloud Modernisation Lead | GenAI Implementation | Accenture". |
| 20 min | Write: a personal "AI skills inventory" — what you can confidently claim, what you're still building | Honesty beats overclaiming. Interviewers can tell. |

---

### Saturday — Consolidate and plan forward

| Time | Task | Notes |

| 30 min | Plan: what does Month 2 look like? What would you build next? | Possible directions: deeper into RAG and production AI systems, AI PM certification, contribute to an open-source AI project, take on an AI workstream at work. |
| 20 min | Reflect: write a "what I know now that I didn't a month ago" summary | A few paragraphs. This is also content for a future post. |

## End-of-month checklist

By the end of 30 days, you should be able to say:

- [ ] I can explain how LLMs work to a non-technical stakeholder in under 3 minutes
- [ ] I have built and shipped at least one real AI-powered tool
- [ ] I can write effective prompts for complex, structured tasks
- [ ] I understand RAG, agents, and tool use conceptually and have seen them in code
- [ ] I can run an AI readiness assessment or governance workshop for a client
